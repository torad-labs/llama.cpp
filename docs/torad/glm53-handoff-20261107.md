## 4. Hardware and build requirements

The target is one process over four physical NVIDIA RTX PRO 6000 Blackwell 96 GB cards, not two independently served pairs. The November 6 hardware record lists four RTX PRO 6000 Blackwell Server Edition GPUs, each reporting 97,887 MiB, with driver 580.95.05. DP ownership is `sequence_id % device_count`. Attention/KV, recurrent state, k-pool and MTP hidden storage follow the sequence owner. Dense weights are replicated; routed experts are partitioned, with gathers and reductions around the expert work. This makes one active session a bring-up check, not the throughput target.

## 7. What data was collected and what it measures

### A. Concurrent-throughput corpus: public repository documentation

The November 6 staged corpus is:

- `.Codex/analysis/glm53-qualification-20261106/upload/public-corpus.txt`
- 351,125 bytes; SHA-256 `fca56be516ba5a724c9812619a3c0a31fcdda209a74fcd1080868e051630700d`.
- It contains labeled public llama.cpp documentation excerpts; its opening is `docs/android.md`. This handoff checked the file's size and hash against the retained run's corpus hash.

The workload repeats the public corpus, gives each session a distinct prefix, renders through `/apply-template`, tokenizes through the server, and selects an exact token depth. It retains the tail containing the request. The current `workload.py` first generates 16 warmup tokens per session, appends them to the conversation, then measures a cached continuation. The historical run used its own packaged workload version; do not overwrite that source with today's implementation and call it the same run.

The inspected historical 36-session leg used 512 initial context tokens, 256 requested output tokens per session, temperature 1.0, top-p 0.95, repetition penalty 1.1 over 256 tokens, `ignore_eos`, and seed `530 + slot`. It retained raw responses and token bursts, prompt hashes, cache counts, actual draft/accept counters, timings and GPU memory.

This is a reproducible load generator, not a benchmark of coding ability, factual accuracy, retrieval quality or safety. A `passed: true` in its run record means the workload/measurement checks passed, not that the answers were semantically graded.

### B. Long-context, tool-history-shaped data

`dp_longctx.py` builds synthetic conversations from a public source tree: a system prompt, twelve tool definitions, a user request, and Read calls/results. It uses the server's template and tokenizer to count the real rendered context. Later turns append the previous answer, a new question and another Read, preserving the prefix.

It measures fill cost, cache retention, continuation delivery, concurrency and VRAM. A turn that re-evaluates over a quarter of its context is reported as lost cache. It preserves partial JSONL results when a long run is interrupted. The tool-history shape is not an end-to-end autonomous coding-task evaluation: these are scripted histories, not evidence that generated tool actions solved a repository task.

Use only public, allowlisted corpus content on a rental. Do not point this tool at the user's home, private conversations, LoRA files, encounters, secrets, or arbitrary project folders.

### C. Component and synthetic-model correctness fixtures

The existing tests exercise expert partitioning, empty/nonlocal expert rows, routing/quantization sharing, captured replay, graph generations, ownership, MTP acceptance/rejection, slot reuse, checkpoint save/restore, hidden-row ordering and prompt admission. Small synthetic models and logical ranks make those paths testable locally.

These establish implementation behavior for the tested paths. They do not establish the selected full model's task quality, natural MTP acceptance rate, four-card performance or 36-way populated long-context capacity. Untrained MTP fixtures that force acceptance are especially not acceptance-rate benchmarks.

### D. Full-model distribution checks

The retained docs report a corrected November 3 candidate at 2K matching its earlier reference within the native reference format's precision in each layout: tensor mean KL 0.000000; DP -0.000001; 100% top-token agreement in each. The small negative reported KL is a quantized-reference numerical floor, not negative mathematical divergence.

The same historical account reports four-card DP versus tensor KL 0.013567. That does NOT meet the requested absolute 1e-6 contract. Batch-shape controls and aligned intermediate captures support arithmetic-order sensitivity but do not prove every final difference harmless.

## 8. Measurements to keep separate

1. **Common-overlap decode throughput:** `measure.common_decode_window` uses `(latest first burst, earliest last burst]`. It counts whole delivered token bursts inside that same interval for every stream. Aggregate = total counted tokens / interval. Per-session values use that same interval; the report's headline is their median. No interval means unavailable, not zero or a guessed rate.
2. **Whole-request wall throughput:** delivered tokens divided by the group's elapsed request time. It includes scheduling/first-token costs that the common decode interval excludes. Do not substitute one for the other.
3. **Server decode timing:** useful diagnostic per-request timing; do not sum request-local rates and call that aggregate delivery.
4. **Prefill and latency:** retain actual populated tokens, fill wall time, first-token delay, per-stream completion and burst timings. Mixed prefill/decode needs its own run.
5. **MTP:** retain actual drafted/accepted tokens, active cohort and effective behavior. Maximum depth two is adaptive, not evidence that every round used two drafts.
6. **Memory:** retain samples during load, prefill, decode and captures on every physical GPU. Reserved cells, successful startup and local logical ranks do not prove populated capacity. `server_matrix.py:111-133` stops its owned server below 4,096 MiB free on any selected card or on deadline.
7. **Profiling:** Nsight kernel durations, busy unions, host ranges, communication waits and byte counts describe different things. Do not add overlapping durations or treat a category total as a guaranteed wall-time saving.

## 9. How to use the workload tools on an approved machine

The staged matrix is not a standalone repo-root command. It expects an already prepared root with `engines.py`, `engines/<label>/bin`, each engine's `SOURCE`, the pinned model, public corpus, copied script assets, and `results/selected-gpus.json` containing four selected physical GPU identities. The historical `upload/manifest.json` and `upload-engines/engines.json` show this bundle layout. Do not run the old `stage.py`, `follow*.sh`, `pass*.sh` or teardown scripts blindly: they describe an earlier rental/window and may carry obsolete host identifiers or deadlines.

For an already running server and an appropriately staged root, this is the workload CLI shape (it does not control server startup):

```sh
python3 scripts/glm53/workload.py \
  --root /workspace/glm53-qual --name candidate-internal-active36-ctx512 \
  --binary /workspace/glm53-qual/engines/candidate/bin \
  --depth 2 --port 8102 --slots 36 --active 36 --context 512 --tokens 256 \
  --deadline "$WORK_DEADLINE_EPOCH" --launch-json "$ACTUAL_LAUNCH_JSON"
```

Use a new run name. `WORK_DEADLINE_EPOCH` must fit inside the approved, independently armed provider stop window with time reserved for collection. Preserve the launch record and actual source/binary identities. `workload.py` does not itself enforce the matrix's VRAM guard or shut down the provider; use the prepared guarded controller for a full qualification run.

For a declared long-context continuation experiment against the running server:

```sh
python3 scripts/glm53/dp_longctx.py \
  --server http://127.0.0.1:8102 --corpus "$PUBLIC_SOURCE_CORPUS" \
  --context-tokens 400000 --streams 1 --turns 3 --reply-tokens 256 \
  --timeout "$REQUEST_TIMEOUT_SECONDS" --out "$NEW_RESULT_JSON"
```

Increase offered load only within the approved workload and demonstrated capacity. The long-context driver defaults to no request timeout, and it does not own the provider stop. Supply a bounded timeout and a new output path; the driver replaces its corresponding partial JSONL file. A one-session long-context result cannot certify 36 simultaneous sessions.

For a matched candidate comparison, freeze the actual source first; keep pack, projector presence, device group, reservation, context occupancy, sampling, corpus, template and build flags fixed. Compare current internal and current hybrid transport without changing other controls. Confirm actual transport and actual capture replay. Record both short steady decode and mixed prefill/decode, then populated long contexts. An ABBA ordering is supported by existing serving tooling, but the historical two-card controller is not interchangeable with the four-card matrix.
