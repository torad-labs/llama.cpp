# Inkling 2 Small on four PCIe Blackwell GPUs

The subsequent rental used four 96 GB RTX PRO 6000 Blackwell Server Edition cards. [Physical measurements and serving results](12-four-card-serving.md)

This review targets the abliterated Q3_K_M text model, four 96 GB RTX PRO 6000s in tensor parallel, 23 sessions, F16 global KV, a 2,359,296-token shared pool and a 294,912-token window per session. A cold 262,144-token coding prompt arriving while 22 clients generate is the mixed workload. The GLM production report describes two PCIe switches. The local measurements used one RTX 5070 Ti (SM120). Target-host output tokens/s, effective PCIe bandwidth and the best transport remain open. [GLM deployment](https://github.com/torad-labs/llama.cpp/issues/255) · [Serving profile and earlier qualification](10-serving-campaign-review.md)

## Remove padded bytes from host-staged gathers

Inkling runs two hidden-state convolutions per layer, one after attention output projection and one after the weighted expert result. In tensor mode, the reduced hidden state is already available on each rank. The scatter is a local layout operation. Each rank convolves its own channels, then the gather reconstructs the whole hidden row for the subsequent computation. There are 96 such gather sites across 48 layers. A trace of three 23-row passes through a 48-layer, width-512 fixture observed 288 hidden gathers and 144 expert reductions. Every expert reduction carried the locally weighted top-eight sum, one hidden tensor per layer. The real target width is 4,608. [Model graph](../../../../src/models/inkling2.cpp) · [Meta backend](../../../../ggml/src/ggml-backend-meta.cpp)

The existing internal host gather stages a padded tensor from each rank and reads every peer's padded tensor. The new Inkling launcher option `--reduction-route host-sliced` uses the same host route for numeric reductions. For aligned gathers with verified ownership, a rank publishes its own pieces once to mapped host memory and reads just the pieces it lacks. The rank layout can repeat in every token row. Empty owners, chunk boundaries inside rows and CUDA Graph replay use the same publication and arrival protocol as the existing gather. Other layouts retain the generic implementation. The default stays `host` pending physical interconnect timings. [CUDA collective](../../../../ggml/src/ggml-cuda/allreduce.cu) · [Launcher](../../../../scripts/inkling2/serve.py)

For one full FP32 hidden tensor of size S and four ranks, the original payload is 4S written to host and 12S read. The sliced gather writes S and reads 3S. The table counts both directions across all cards and excludes protocol flags, cache-line effects, numeric reductions and all other traffic. These are payload counts derived from the copy operations.

| Shape at a gather | Full tensor | Original host payload | Sliced host payload |
|---|---:|---:|---:|
| 23 decode rows, 4,608 channels | 414 KiB | 6.469 MiB | 1.617 MiB |
| 2,048 prefill rows, 4,608 channels | 36 MiB | 576 MiB | 144 MiB |

Four logical ranks on one physical GPU exercised the public communication API. The captured 23-row graph contained four launches of the sliced kernel with mapped host addresses. A 36 MiB prefill gather spanned 36 chunks per rank. Across nine shapes, three replays and two eager calls per shape, all 233,588,260 checked words matched. Six aligned layouts selected slicing and three unaligned layouts selected the generic gather. In a server run with the mixed-Q3 fixture, the host-sliced route scheduled 5,816 sliced gathers. A cold 262,144-token reader generated its requested 128 tokens with all 22 peers spanning the prefill. Resident and RAM-restored continuations both reused 262,144 tokens. [Local gather results](data/rtx5070ti-host-gather.csv)

The hybrid flash-attention graph also shares the physical row indices used for K and V in each of its two KV caches. All 21 traced fixture graphs went from four index uploads to two. That removes 128 KiB across four ranks for a 2,048-token microbatch, or 1,472 bytes for 23 decode rows. Two cold requests returned the same generated tokens and top-128 log probabilities as the earlier binary. With transposed V, the server still uploads separate indices. [Graph inputs](../../../../src/llama-graph.cpp)

## Reuse cache reads inside each SM120 GPU

Inkling's 48 query heads share eight KV heads. Each TP4 rank has 12 query heads and two KV heads. The model has 40 sliding-window layers and eight global-attention layers. The global layers see the full visible context during long coding sessions. vLLM found that a six-to-one group missed its normal packing path and reported 15.1 to 4.8 ms for a batch-one 100k decode step. Its datacenter kernel uses tcgen05. The independent TensorFold Inkling implementation also groups query heads by KV head. On SM120 the fork now computes three query heads per KV load in its sparse packed decoder. Six heads per warp increased register use in the local prototype. [vLLM engineering report](https://vllm.ai/blog/2026-11-12-inkling2-small) · [TensorFold Inkling CUDA source](https://github.com/swbiggart/TensorFold-upstream/blob/dee0906d3d18db50231d63c3112b5bf19942c210/zig/kernels/cuda/inkling2_attn.cu) · [Instruction targets](https://docs.nvidia.com/cuda/parallel-thread-execution/)

The following are paired medians for **one rank-shaped attention operation**, including the partial-result merge. They use 23 balanced sequences, F16 KV and physical cell runs of 128. Each of seven timing rounds measured both implementations on the same GPU, rotating the order. The old kernel and rebuilt library ran in the same process. The updated path preserves the reduction order and scratch allocation.

| Active pool | Original | Updated |
|---:|---:|---:|
| 65,536 cells | 0.333 ms | 0.195 ms |

All 82 comparisons produced identical output values. They cover F16 and Q8_0, 8/16/23/32 query rows, contiguous runs and interleaving, and both sink modes. Three-head dispatch requires six query heads per KV head and at least 65,536 cells. It retains the packed decoder's existing visibility and batch guards. [Paired results](data/rtx5070ti-grouped-gqa.csv) · [CUDA kernel](../../../../ggml/src/ggml-cuda/fattn-rel-decode.cuh)

A separate forced-path experiment shows where a future dispatch change could help. With 23 sessions each reading 262,144 tokens, including a common 196,608-token prefix, the normal F16 path took 29.02 ms and the packed path took 13.37 ms. Each query saw 15.38% of the occupied cells, outside today's one-eighth maximum. At 42.61% average visibility, normal MMA won, 18.33 ms versus 20.90 ms. At fully shared 1M context it won by a wider margin. Measure both the maximum and average visible cells per query before widening dispatch. The high-density comparisons use a different summation from MMA. Over the 23-way 256k case, maximum whole-output difference was 0.0000449. The 16 FP64 spot checks gave maximum absolute error of 9.58e-10 for packed and 7.51e-6 for MMA. Real-model logits and 23-session speed are still unqualified for this experimental path. The Chinese-language discussion on 产品派 raised deployment cost and VRAM. The 巴巴小站 forum described the stock checkpoint's 500 GB deployment guidance. That figure applies to the published native format. Yu Guangba's Chinese technical note traced six-head packing and the layer-boundary fusions to the vLLM implementation. I found no Chinese forum post with a reproducible 23-stream run of abliterated Q3_K_M on four RTX PRO 6000s. The community discussion and the primary engineering measurements answer different questions. The public Inkling implementation is a patch set over TensorFold. Its published four-GB10 setup used a 200G RoCE switch and stock NVFP4/MXFP8 experts. It reports 30.95 tok/s for plain single-stream code and 60.8 tok/s for drafted chat code. At a matched 32k allocation, four streams went from 62.6 to 102.6 aggregate tok/s, while eight went from 79.0 to 81.0. The authors verified up to eight streams. The published implementation and benchmarks provide a reason to test adaptive drafting at light load. They provide no rate for 23 active RTX sessions. The abliterated checkpoint's 3.188 GiB BF16 draft matches the stock draft file by SHA-256. Upstream llama.cpp PR 32218 has a dedicated converter and RNN. Its host activation path copies eight FP32 vectors of width 4,608 per target token, 144 KiB per token or 288 MiB per 2,048 input rows. A device-resident handoff matters on PCIe. Seven proposed tokens can turn 23 ordinary decode rows into 184 target verification rows. Budget roughly 12.55 GiB extra across the box for draft weights, F16 global draft KV at this pool size and the 23 sliding windows, before scratch, rollback, replication and padding. Acceptance, peak VRAM and restored-session correctness depend on the real derivative. ## Further PCIe savings

**Cache positions and sequence membership on device.** The global attention inputs refresh the occupied span of the position vector and the packed mask on every microbatch, including retained graphs. For global span N and Q rows, the current input payload is 4N + NQ/8 bytes per rank. At N = 2,359,296, this totals 61.875 MiB across four GPUs for 23 decode rows, and 2,340 MiB for 2,048 prefill rows. These are maximum-shape payload counts. Prompt scheduling, physical placement, sharing and the active extent determine how often the server pays them. A single-sequence prefill could transmit one membership row (288 KiB per rank at full extent) and construct its 2,048 causal masks on the GPU. For decode, update the stable device position array from changed physical cells and keep membership by sequence ID. Both mirrors must follow slot reuse, shared prefixes, restore to a new cell, failed evaluations and graph lifetime. [KV inputs and mask construction](../../../../src/llama-kv-cache.cpp) · [Existing device mirror and resynchronization pattern](../../../../src/llama-kv-cache-kpool.cpp)

**Reduce directly to the convolution's channel owners.** Today's projection is reduced onto all ranks before each takes its channel slice. The existing owner-reduce detection recognizes a contiguous result directly consumed by a same-layout row scatter. Inkling reshapes and permutes before scattering. Its channel slices repeat for each token. A strided reduce-scatter could avoid distributing the full result before the convolution, then gather only the convolved slices. Preserve the BF16 wire's rank-sum order and compare restored convolution tails. vLLM's reported 22% reduction in TP4 8k prefill step time used sequence parallelism on its own hardware. The fork already divides convolution channels among ranks. [vLLM prefill implementation](https://vllm.ai/blog/2026-11-12-inkling2-small) · [Fork split planner](../../../../ggml/src/ggml-backend-meta.cpp)

**Use the measured PCIe topology for reductions.** The internal peer probe checks every ordered GPU pair and drops the card-to-card route when the full group fails. If both same-switch pairs have usable peer access but the cross-switch links are poor, a two-stage reduction could first combine the two partials on each switch and then exchange the two group results. Confirm the peer-access matrix and simultaneous bidirectional bandwidth under load before implementing this. BF16 partial rounding and the order of the sums can change model output. The host-sliced gather above also works when every GPU-to-GPU peer link is unavailable. [CUDA peer probe](../../../../ggml/src/ggml-cuda/allreduce.cu)

**Prune the last expert layer during long prefill.** A captured 257-token prompt still reduced all 128 final-layer expert results in each full microbatch while returning one logit row. With four convolution taps, no rollback and one sequence, a state-only chunk needs its final three raw FFN rows. A terminal logit needs four. That changes the last layer's 2,048-row expert reduction from 36 MiB to 54 or 72 KiB. Additional output positions, checkpoint tails and speculative rollback require their own rows. This remains a proposed change to one of 48 layers.

The first four-card comparison should use the same calibrated pack, token IDs, F16 KV, effort and uncapped serving policy. Compare host, host-sliced and engine-selected routes. Capture the actual two-switch topology and peer-access matrix. Measure aggregate delivered output tok/s and each client's rate under 23-way decode, then the 262k reader's time to first token and the other 22 clients' p95 delivery gaps. Record per-device PCIe TX/RX with the same workload and separately from RAM restores. This isolates the practical value of fewer transferred bytes from the GPU-local attention gain.
