# Decode comparison surface

Reading this as: an inference comparison tool for Marcos and the inference team, seated at the instrument bench under daylight -- composed, still, dense.

1. Register and seat: an operating screen at a 3840 x 2050 desk viewport. The comparison fills the available width; small screens use a stacked, scrollable ledger rather than miniature desktop columns.
2. Elements: the workload settings are a control strip; ideal and recorded values share a comparison ledger; selected evidence opens in an attached inspector. A four-GPU activity strip shows measured occupancy, not decorative progress.
3. States: start with the real 4096 capture and the 40-session ideal. Show the workload mismatch immediately. Layer, kernel, copy and API views expose different measurement scopes without mixing their totals.
4. Navigation: choose a capture, select a view and device, search, then select a row for equations, raw sample events and sources. Local import replaces the capture with an explicit error/recovery state for invalid files.
5. Motion: no entrance animations. Selection and expanded details change immediately; no measurement depends on animation.
6. Disclosure: workload identity and evidence limitations stay visible. Transport parameters, percentile definitions and provenance expand when needed. Missing values read 'Not measured' or 'Not attributed', never zero.
7. Prose: use ordinary operator labels and physical units. No fictional speedup or simulated capture. Source Serif 4/Fraunces carry reading/display text; instrument numerals use IBM Plex Mono with readable fallbacks.

Palette: warm paper and iron-gall text; blue identifies ideal budgets, orange identifies recorded measurements, and amber identifies comparison warnings. Dark mode uses a warm dark ground with an opaque chart surface. Missing measurements retain their track with a neutral hatched unknown marker rather than a numeric zero. The two summary strips have independent denominators: ideal cycle components and captured kernel-activity share.

The page uses a full-width three-column workbench at the desk, a two-column arrangement with the inspector below at laptop widths, and one page-scroll column on phones. Long data sets are paginated rather than hidden in fixed-height panes. Boundaries primarily align the comparison columns, not a card mosaic. The original side-by-side request fixes the composition, so no alternate identity or design interview is needed.
